# 接口协议契约文档

## 1. 协议概述

本协议定义了网络聊天室系统中客户端与服务器之间基于 WebSocket 的实时通信协议。所有消息均采用 JSON 格式进行序列化和反序列化。

### 1.1 通信方式

- **协议**: WebSocket (RFC 6455)
- **传输层**: TCP
- **编码格式**: UTF-8
- **序列化**: JSON

### 1.2 消息基本结构

所有消息均遵循以下 JSON 结构：

```json
{
  "type": "MESSAGE_TYPE",
  "from": "sender_username",
  "content": "message_content",
  "time": "yyyy-MM-dd HH:mm:ss",
  "isNSFW": false,
  "iv": "encryption_iv",
  "id": "message_unique_id",
  "conversationId": 123
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | 消息类型，枚举值 |
| from | string | 是 | 发送者用户名 |
| content | string | 是 | 消息内容，可能是纯文本或 JSON 字符串 |
| time | string | 否 | 发送时间，格式为 `yyyy-MM-dd HH:mm:ss`（北京时间） |
| isNSFW | boolean | 否 | 是否为 NSFW 内容，默认 false |
| iv | string | 否 | 加密初始化向量，加密消息时使用 |
| id | string | 否 | 消息唯一标识 |
| conversationId | integer | 否 | 会话 ID，用于区分不同的聊天会话 |

## 3. 接口详细定义

### 3.1 认证接口

#### 3.1.1 用户注册 (REGISTER)

**请求方向**: Client → Server

**入参**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `"REGISTER"` |
| from | string | 是 | 客户端标识（可为空或固定值） |
| content | string | 是 | JSON 字符串，包含注册信息 |

`content` 字段格式：
```json
{
  "username": "user123",
  "password": "password123",
  "avatar": "/avatars/users/user123/avatar.png"
}
```

| content 子字段 | 类型 | 必填 | 说明 |
|----------------|------|------|------|
| username | string | 是 | 用户名，唯一 |
| password | string | 是 | 密码，明文传输（建议生产环境加密） |
| avatar | string | 否 | 头像路径（ZFile 相对路径） |

**出参**:

成功响应 (`AUTH_SUCCESS`):
```json
{
  "type": "AUTH_SUCCESS",
  "from": "server",
  "content": "uuid_value|/avatars/users/user123/avatar.png",
  "time": "2024-01-15 10:30:00"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| type | string | `"AUTH_SUCCESS"` |
| from | string | `"server"` |
| content | string | UUID 值，若有头像则格式为 `uuid|avatar_path` |

失败响应 (`AUTH_FAILURE`):
```json
{
  "type": "AUTH_FAILURE",
  "from": "server",
  "content": "client",
  "time": "2024-01-15 10:30:00",
  "conversationId": null
}
```

**权限**: 无需认证

**错误码**:
| 错误码 | 说明 |
|--------|------|
| 1001 | 用户名已存在 |
| 1002 | 注册信息格式错误 |
| 1003 | 注册信息解析失败 |
| 1004 | 注册失败，数据库错误 |
| 1005 | 注册失败，服务器内部错误 |

## 7. 会话类型说明

系统使用 `conversation_id` 来区分不同的聊天会话，会话类型分为三种：

| 类型 | 说明 | 成员数量 |
|------|------|----------|
| ROOM | 房间会话（群聊） | ≥2 |
| FRIEND | 好友会话（私聊） | 2 |
| TEMP | 临时会话（非好友私聊） | 2 |

### 会话 ID 前缀约定

客户端在显示时使用前缀区分会话类型：
- `#` 前缀表示房间会话，如 `#技术讨论群`
- `@` 前缀表示好友/私聊会话，如 `@user1`

## 8. 数据格式约定

### 8.1 时间格式

所有时间字段统一使用北京时间（Asia/Shanghai），格式为 `yyyy-MM-dd HH:mm:ss`。

### 8.2 头像路径

头像路径使用 ZFile 相对路径，格式为 `/avatars/users/{username}/avatar{extension}`。

### 8.3 文件命名规则

文件上传时生成唯一文件名，格式为：`{原始文件名}_{时间戳}_{8位随机字符串}.{扩展名}`

### 8.4 消息 ID 格式

消息 ID 格式为：`{MESSAGE_TYPE}_conversation_{conversation_id}_{database_id}`

## 9. 安全注意事项

1. **密码存储**: 用户密码使用 BCrypt 算法加密存储，不会以明文形式保存。
2. **传输安全**: 建议生产环境使用 WSS（WebSocket Secure）加密传输。
3. **消息时间验证**: 服务器验证消息时间与服务器时间偏差不超过 ±5 分钟。
4. **权限验证**: 所有操作都进行权限检查，确保用户只能操作自己有权限的资源。
5. **SQL注入防护**: 使用 PreparedStatement 防止 SQL 注入攻击。
6. **会话防重复**: 同一用户名只能在一处登录，新登录会拒绝或踢掉旧会话。
